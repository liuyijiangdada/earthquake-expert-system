基于动态-静态知识协同的地震灾害问答系统——硕士学位论文研究内容规划
一、研究背景与核心问题
地震灾害应急管理贯穿震前防御、震中响应和震后恢复三个阶段。不同阶段用户的信息需求差异显著：震前需要长期稳定的防御知识，震中亟需时效性强的实时情报，震后则需要重建与心理干预等中长期信息。现有灾害问答系统大多依赖单一信息通路，难以同时满足静态知识的系统性与动态信息的实时性。

本研究拟构建一套基于“动态-静态知识协同”的地震灾害问答系统，核心研究问题是如何设计一种融合静态结构化知识库与动态实时信息的知识协同架构，使问答系统能够在震前、震中、震后为用户提供准确、及时、可操作的多模态信息服务。

二、系统总体思路（简化版）
系统采用“静态知识引擎 + 动态知识引擎 + 协同调度”的架构：

静态知识引擎：存储地震科普、应急预案、避险技能等长期稳定的知识（如知识库或知识图谱）。

动态知识引擎：接入地震台网实时数据、官方通报等动态信息（通过API或爬虫）。

协同调度器：根据问题的时效性自动判断优先调用静态还是动态知识，必要时进行混合检索与融合生成。

多模态输出模块：在答案中附加图片、地图、视频链接、导航链接等。

四、深度思考：让“三阶段”成为系统设计核心
4.1 核心科学问题
地震灾害场景下，用户的信息需求在时间轴上呈现“静态知识→动态情报→混合知识”的连续演化规律。系统需要自动感知并适应这种演化，而非依赖人工切换模式。

4.2 知识时效敏感性曲线
为每个知识点标注“半衰期”（如“抗震设防烈度”半衰期10年，“当前余震概率”半衰期10分钟），系统根据半衰期自动路由知识来源。

4.3 不确定性感知的调度器
系统计算三个指标：

static_confidence：静态知识能否回答的置信度

dynamic_availability：动态信息源是否有相关数据

urgency：问题紧急程度（由关键词“现在/立即/多大”等激发）

决策规则示例：

若紧急程度高且动态数据可用 → 优先动态，静态提供可执行模板备选

若静态置信度 > 0.9 → 使用静态，同时主动询问“是否需要最新动态？”

否则 → 混合检索，并告知用户信息可靠性等级

5.3 技术实现（简化）
预建媒体资源库：收集30~50张图片、10~15个视频链接，标注关键词和适用阶段。

关键词匹配：用户问题经分词后匹配媒体资源库，返回相关媒体URL。

动态生成：调用地图API生成静态地图截图；用Matplotlib生成余震时序图。

LLM融合输出：在生成答案时自然插入![描述](url)或[链接文字](url)。

八、论文创新点
三阶段全周期覆盖：同时服务震前、震中、震后，突破单一阶段限制。

动态-静态知识协同机制：基于时效性和不确定性的自适应调度。

多模态输出：融合图片、地图、视频链接，提升信息可理解性与可行动性。

轻量化实现：不依赖复杂大模型训练，易于复现和部署。
