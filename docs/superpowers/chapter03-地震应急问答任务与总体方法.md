## 3.1 任务定义与评价指标

### 3.1.1 任务形式化与用户交互形式

**任务目标。** 给定用户以自然语言提出的地震应急相关问题，系统输出一段中文回答，在满足可读性的前提下，尽量**与本地知识图谱中的可验证事实一致**，并合理利用**应急知识库检索片段**补充步骤与表述。问题类型可覆盖：震情查询（地区、震级阈值等）、应急避险与处置要点、概念性科普等，但不强制限定为单一模板句式。

**形式化描述。** 记用户问句为 $q$，系统维护的知识图谱为 $G$，应急知识分块集合为 $\mathcal{D}=\{d_1,\ldots,d_n\}$。大模型问答路径（`query_type: llm`）可抽象为：

$$a = f_\theta\bigl(\Phi(q, G), \Psi(q, \mathcal{D}), q\bigr)$$

其中 $\Phi$ 表示依据规则从 $G$ 中抽取并线性化得到的**图谱上下文**（无命中时为空或占位）；$\Psi$ 表示基于句向量的 **Top-K 检索**得到的参考资料拼接；$f_\theta$ 为带 LoRA 的生成模型；$a$ 为最终回答。纯图谱查询路径（`query_type: kg`）则不经 $f_\theta$，直接返回结构化列表，用于前端列表与筛选，记为 $r=\mathrm{Query}_G(q_{\mathrm{params}})$，其中 $q_{\mathrm{params}}$ 为地区、震级区间、深度区间等显式参数。

**用户交互。** 浏览器侧将对话输入封装为 `POST /api/query`，`params.input` 承载 $q$。列表与筛选使用同一接口的 `kg` 分支，避免大模型参与排序与过滤，以降低延迟并保证结果可复现。数据刷新通过 `POST /api/update-data` 触发，使 $G$ 中事件节点与外部目录同步（实现细节见第 6 章）。

### 3.1.2 评价指标与人工/自动评测说明

地震应急问答往往**缺乏唯一标准答句**，且答案可能包含多条事实与步骤，因此评价宜**多维组合**：

**（1）事实一致性。** 对回答中出现的可验证要素（时间、地点、震级、深度等）与图谱或权威检索片段对照，统计**正确 / 错误 / 无法核对**比例，或采用人工二分/三分标注。该指标直接反映「图谱优先」规则是否落实。

**（2）完整性与覆盖面。** 针对若干预设问题（含清单式应急步骤），检查要点是否遗漏；可采用人工打分（如 1～5 分）或检查表（checklist）命中数。

**（3）流畅度与合规性。** 是否满足系统提示中的格式约束（无多余开场白、无禁用强调符号等），可由人工快速二元判断。

**（4）自动指标的局限。** BLEU、ROUGE 等基于 n-gram 重叠的指标对**表述多样**的问答任务区分度有限，仅可作辅助；若存在标准答句的小规模集合，可报告 ROUGE-L 等作为参考，但不宜单独作为结论依据。

**（5）消融对比。** 通过配置关闭 `KG_CONTEXT_ENABLED` 或 `RAG_ENABLED`，在**同一问题集**上比较上述指标变化，用于验证协同机制的贡献（第 7 章给出实验设置与结果）。

## 3.2 协同框架总体设计

### 3.2.1 图谱分支与向量检索分支的职责划分

**图谱分支 $\Phi$ 的职责**是提供**结构化、可核对**的事实与主题—步骤关系，主要包括：

- **地区触发**：当问句命中预设省级行政区名称时，调用图谱按地区检索地震事件，取前若干条格式化为「知识图谱信息」段落（含时间、震级、深度、烈度、描述等字段）。
- **震级条件触发**：当问句同时包含「震级」与「大于 / 高于」及数值模式时，解析阈值并查询不低于该震级的事件摘要。
- **应急语境触发**：调用 `query_emergency_context` 等与应急主题、处置步骤相关的子图查询，将结果追加至图谱上下文。

若未命中任何规则或查询结果为空，图谱段落在提示中以「（无）」占位；若整体关闭图谱上下文，则显示「（本路径已关闭）」以便实验对照。

**向量检索分支 $\Psi$ 的职责**是从 `emergency_knowledge.json` 等语料中召回与 $q$ **语义相近**的片段，作为【参考资料】。实现上对 $q$ 与各 chunk 编码后做余弦相似度排序，取 Top-K，并按标题与正文截断拼接。RAG 未启用或索引未加载时，参考资料段为「（无相关条目）」等占位，不阻断生成流程。

**分工原则。** 规则上明确：**数值、时间、震级、地点等可验证事实以知识图谱为准**；参考资料用于**步骤说明、表述补充**；二者均未命中时，允许模型基于参数知识回答并声明未命中本地库，以降低「沉默」体验，但须在实验中单独讨论其风险。

### 3.2.2 端到端协同推理流程

单次 `llm` 请求的处理顺序与第 2 章数据流一致，此处从**方法角度**归纳：

1. **构造图谱字符串** $s_G=\Phi(q,G)$（受 `KG_CONTEXT_ENABLED` 控制）。
2. **构造检索字符串** $s_R=\Psi(q,\mathcal{D})$（受 `RAG_ENABLED` 与索引可用性控制）。
3. **拼装用户提示**：将「角色说明—【知识图谱】—【参考资料】—规则与回答要求—【问题】」合并为单条 user 内容，其中 **$q$ 固定置于末尾**，以便在超长提示下采用**左侧截断**时仍保留问题与后续生成标记。
4. **套入对话模板**：与微调一致，使用 `<|system|>…</s><|user|>…</s><|assistant|>` 形式拼接后再经分词器编码。
5. **解码生成**：在最大输入长度、温度、Top-p、重复惩罚与 n-gram 防重复等超参控制下自回归生成，截取新增 token 解码为 $a$ 并返回 JSON。

该流程将**结构化查询**与**稠密检索**在同一提示内对齐，使 $f_\theta$ 在一次前向生成中完成融合，而无需额外的多轮工具调用协议（实现上更简单，适合毕业设计级系统）。

## 3.3 与单一图谱 / 单一检索方案的对比思路

为验证「协同」的必要性，构造以下**对照设置**（与配置文件一一对应）：

**（1）仅大模型（无图谱上下文、无 RAG）。** 将 `KG_CONTEXT_ENABLED` 设为假且关闭 RAG 或使索引为空，提示中图谱与参考资料均为关闭或空占位。用于观察纯参数记忆在事实性与应急步骤上的表现。

**（2）仅图谱增强。** 开启 `KG_CONTEXT_ENABLED`，关闭 `RAG_ENABLED`。适用于强依赖震情与结构化事实的问句；对长文本式条例补充可能不足。

**（3）仅向量检索增强。** 关闭 `KG_CONTEXT_ENABLED`，开启 RAG。适用于概念与流程类问题；对精确事件列表与数值约束可能弱于图谱。

**（4）全协同（默认）。** 图谱与 RAG 同时开启，提示规则如第 3.2 节所述。

对比时保持**同一基座与 LoRA 权重、同一解码超参与同一问题集**，仅切换上述开关，比较事实一致性、完整性及典型案例行为差异。预期在**既含事实查询又需条文补充**的混合问句上，全协同整体更稳；在极端单一类型问句上，某一基线可能略优，可在第 7 章案例分析中讨论。

## 本章小结

本章将地震应急场景下的应用需求形式化为「图谱上下文 + 检索上下文 + 用户问题」驱动的大模型生成任务，并区分 **llm** 与 **kg** 两种交互路径。评价上建议以事实一致性、完整性为主，辅以格式合规与消融实验。协同框架上明确图谱分支与向量分支的职责边界及提示中的优先级规则，并给出端到端推理步骤与四种基线对照思路，为第 4～6 章的具体构建、检索与实现及第 7 章实验设计提供统一参照。
