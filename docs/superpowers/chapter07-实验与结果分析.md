## 7.2 基线设置与评价方法

### 7.2.1 基线系统（仅 LLM、仅 KG、仅 RAG、全协同）

在**同一基座与 LoRA 权重、同一解码超参**下，仅通过配置切换上下文来源，构造四类设置：

| 编号 | 设置名称 | KG_CONTEXT_ENABLED | RAG_ENABLED | 说明 |
|------|-----------|---------------------|-------------|------|
| B0 | 仅大模型 | False | False | 提示中图谱与参考资料均为关闭/空占位，考察纯参数记忆。 |
| B1 | 仅图谱增强 | True | False | 有结构化事实与应急子图，无向量检索片段。 |
| B2 | 仅 RAG 增强 | False | True | 有参考资料 Top-K，无图谱查询上下文。 |
| B3 | 全协同（系统默认） | True | True | 图谱与 RAG 同时注入，对应完整方法。 |

每类设置需**重启服务或热改配置后重新加载**（视实现而定），再在同一问题集上批量请求 `query_type: llm` 并保存回答。

### 7.2.2 评测问题集构造与打分规则

**问题集构造建议**：

1. **事实类**：包含省名、震级比较等易触发图谱查询的问法，用于检验与目录一致性。  
2. **规程类**：避险、室内/室外等易触发应急子图或 RAG 的问法。  
3. **混合类**：既含地区又含「怎么办」等，检验协同是否优于单一路径。  
4. **弱相关或开放类**：本地库可能无命中，检验模型是否按规则声明「未命中」。

题量可根据答辩要求设定（如 20～50 问），并保留**标准核对要点**（非必须逐字标准答案）：例如每条问题列出应从图谱中核对的关键字段或应覆盖的应急要点编号。

**打分规则**：

- **事实一致性**（0/1 或 0/0.5/1）：回答中可验证事实是否与图谱或检索片段一致。  
- **要点完整性**（Likert 1～5 或要点命中数/总数）。  
- **合规性**（0/1）：是否违反系统提示中的格式约束。

可由**两名标注者**独立打分后取平均或 Cohen’s kappa 报告一致性；单人研究则需说明局限。

### 7.3.2 典型案例与失败样例讨论

**典型案例（建议 2～3 个）**  

- **协同有效**：展示用户问题、B0/B3 回答对比、图谱与 RAG 命中摘要，说明全协同如何同时利用结构化事实与检索表述。  
- **图谱主导**：某省近期地震类问题，说明 B1/B3 如何利用 `location CONTAINS` 结果约束数值。  
- **RAG 补充**：规程类问题在图谱步骤与检索片段上的互补。

**失败或边界样例（1～2 个）**  

- **触发规则未命中**：问法未包含省名或触发词，导致图谱为空，仅依赖 RAG 或参数知识。  
- **截断或复读**：极长上下文下左侧截断导致信息丢失，或解码复读；可对应调整 `LLM_INPUT_MAX_TOKENS`、`repetition_penalty` 的讨论。  
- **幻觉仍未消除**：即使 B3，在库外事实上仍错误——强调方法为**减轻**而非绝对消除幻觉。
