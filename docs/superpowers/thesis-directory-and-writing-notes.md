## 各章撰写要点（对照工程实现）

### 第1章 绪论

- **1.1**：从地震应急信息公开、科普与处置指引需求切入；点出「要快、要准、要能核对来源」。
- **1.2**：综述 KBQA、Graph RAG、文本 RAG、领域微调四条线，各 2～3 篇代表工作即可，末尾用一小段指出「图谱 + 向量」协同在应急问答中的研究空隙。
- **1.3**：创新点建议写 3 条以内、可检验：协同流程、触发式图谱查询 + 向量 Top-K、本地 LoRA 与长提示截断策略等（与代码一致）。
- **1.4**：按上表各章用一段话概括，避免与摘要重复。

### 第2章 相关技术与理论基础

- **2.1**：画 1～2 张图——（1）模块架构图：前端 / Flask / Neo4j / RAG 索引 / LLM；（2）单次问答数据流：与 `process.md` 中「用户输入 → generate_response」一致。可与 `docs/superpowers/specs/2026-03-25-rag-kg-integration-design.md` 对齐表述。
- **2.2～2.5**：教材级定义 + 与后文符号统一（如 Top-K、嵌入维度等）。

### 第3章 任务与方法总览

- **3.1**：输入输出形式（自然语言问句、结构化可选参数）；指标可用准确率/相关性人工分、或简单 F1（若有机打标准答案）；无金标时写明「人工盲评 + 案例集」。
- **3.2～3.3**：用流程图 + 伪代码描述「何时走图谱、何时走 RAG、如何合并」；对比实验设计在此预告。

### 第4章 知识图谱（对齐 `kg/neo4j_kg.py`）

- 写清节点标签、关系、唯一约束；导入优先级（真实目录 + 应急 JSON vs CSV）；Cypher 与触发规则与 `app.py` 中 `generate_response` 分支一致。
- 可配 Neo4j Browser 截图或小规模模式图。

### 第5章 向量检索（对齐 `rag/emergency_rag.py`）

- 分块依据（如按 topic）；嵌入模型名称；余弦 Top-K；`RAG_TOP_K`、`RAG_MAX_CHUNK_CHARS` 等配置在文中说明「取值理由」。

### 第6章 协同与实现（对齐 `app.py`、`config/config.py`、`static/index.html`）

- **6.1.3** 重点写 `tokenizer.truncation_side = "left"` 与「问题在提示末尾」的原因（与 `process.md` 一致）。
- **6.3** 列出主要 API：`/api/query`（`llm` / `kg`）、数据更新接口等；离线环境变量（`HF_HUB_OFFLINE` 等）一笔带过即可。

### 第7章 实验

- 基线：关闭 `KG_CONTEXT_ENABLED` / `RAG_ENABLED` 做消融；表格 + 若干问答截图。
- 诚实写样本量与局限（若仅小样本人工评）。

### 第8章

- **8.1**：对应第3章方法逐条收束；**8.2**：多跳推理、图谱自动更新、更强评测集、模型升级等。
