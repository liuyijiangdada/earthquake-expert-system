## 1. 目标与成功标准

将论文按导师意见应对方案重组为 **6 章制**，充实方法与实验表述，另存标红修改版，使：

1. 结构与应对方案提纲一致（静态知识 → 协同调度 → 落地验证）
2. 十条导师意见均有可定位的回应段落
3. 实验主口径与仓库 `data/eval/table_6_3_summary_60.json`（60 题）一致
4. GraphRAG / KnowledGPT 为设计对比，不虚构同设定复现数值
5. 输出为独立文件，原稿不动；新增/重写段落标红

**非目标：** 新跑 GraphRAG 实验；伪造用户问卷；直接覆盖原稿；追求排版页数精确等于 70（以充实内容与附录逼近，Word 最终页数受图版式影响）。

## 6. 实验与表述约束

**数据源：** `data/eval/table_6_3_summary_60.json`、`data/eval/ablation_results_60.json`。

**须如实写的结论方向（以 JSON 为准，生成时注入）：**
- B3 事实一致性高于 B0/B1/B2
- 要点完整性 B3 并非全面领先（协同更利于事实对齐，不保证更完整步骤覆盖）
- B2 事实分偏低：从分块粒度、嵌入、Top-K、提示可核对片段依赖、评分 proxy 特性分析，并给改进方向

**禁止：**
- 写「显著优于」而无检验时，改为描述性对比；可对 60 题结果做简单显著性讨论（若脚本可算则写入，否则说明未做正式假设检验）
- 把自动 grounding 写成人工评测
- 把关闭动态源的消融写成含动态/地图的主结论

**GraphRAG / KnowledGPT：** 对比维度建议为：图谱构建粒度、是否阶段感知、是否接入实时动态源、调度是否显式。结论强调地震应急「阶段差异 + 时效」上的设计增益，不编造对方分数。

## 7. 实现方式

1. **内容层：** 按第 4 节提纲撰写 `BODY_BLOCKS` 等结构化段落（可复用 `thesis_rewrite_content.py` 中已校准表述，按 6 章重切）。
2. **生成层：** 复制底稿 → 保留封面至摘要前结构 → 替换摘要/关键词 → 自「第一章」至「致谢」前重建 → 标红 → 写出 `_6章修改版.docx`。
3. **数字注入：** `--fill-eval` 读取 60 题汇总 JSON 替换占位符。
4. **插图：** 正文留「图 x-x」说明与建议路径；不强制本次嵌入全部二进制图（可后插），但预留图题。
5. **目录：** 生成正文标题后，提示用户在 Word 中「更新域」刷新目录，或跑现有 `add_thesis_toc.py` 类脚本。

## 8. 风险与边界

| 风险 | 应对 |
|------|------|
| Word 页数仍不足 70 | 附录加厚 + 截图/架构图插入说明；不注水空话 |
| 无 GraphRAG 同设定分数 | 明确设计对比边界，避免被审稿质疑造假 |
| 旧 7 章脚本口径残留 | 新 6 章内容模块独立，不以旧「总体方法独立章」为主线 |
| 标红过多影响提交版 | 交付标红版供导师对照；需要时可再出一版去红正稿（本设计范围外，可另开） |
