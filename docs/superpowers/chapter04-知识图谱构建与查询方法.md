# 第4章 知识图谱构建与查询方法

**说明：** 正文与实现代码 `kg/neo4j_kg.py`、`config/config.py` 及 `app.py` 中图谱上下文逻辑一致。可经 `scripts/export_md_to_docx.py` 导出 Word。

---

## 4.1 模式设计与数据导入

### 4.1.1 实体类型、关系与约束设计

知识图谱采用 **Neo4j** 属性图模型，主要节点标签与语义如下。

**（1）Earthquake（地震事件）**  
表示一次可标识的地震记录，核心属性包括：`id`（业务主键）、`name`、`time`、`magnitude`、`depth`、`location`、`latitude`、`longitude`、`intensity`、`description` 等。事件是问答中**可验证事实**的主要来源。

**（2）Region（区域）**  
表示省级行政区节点，属性以 `name` 为主（如「四川」）。地震与区域通过 **OCCURRED_IN** 关联，便于按行政区划视角组织数据；区域名也可由 `location` 字符串中是否包含省名推断得到。

**（3）EmergencyTopic（应急主题）**  
表示一类应急知识主题，属性包括 `id`、`title`、`category`、`source` 等，对应预案或科普中的主题条目。

**（4）GuidanceStep（处置步骤）**  
表示主题下的有序步骤，属性包括 `id`、`text`、`order`。主题与步骤通过 **HAS_STEP** 连接，关系上可携带 `order` 以与步骤序号一致。

**关系类型补充：**  
- **RELATES_TO**：应急主题之间的关联（如前置、并列关系），可带 `relation_type`。  
- **SUGGESTS_TOPIC**：由某次地震事件指向建议关注的应急主题，用于将目录型数据与规程型知识衔接。

**约束（唯一性）**  
初始化时创建以下约束，避免重复节点与导入冲突：`Earthquake.id`、`Region.name`、`EmergencyTopic.id`、`GuidanceStep.id` 均要求唯一（`IF NOT EXISTS` 创建，适配 Neo4j 多次启动）。

该模式将**事件目录**与**应急规程**统一在同一图内，既支持按时间、地区、震级过滤事件，又支持拉取主题—步骤子图供自然语言上下文使用。

### 4.1.2 地震目录与应急知识的数据来源与导入策略

数据加载在 `Neo4jKG.run()` 中执行：若库中尚不存在 `Earthquake` 节点，则按优先级初始化。

**优先路径（JSON）**  
当 `REAL_EARTHQUAKE_CATALOG_FILE` 与 `EMERGENCY_KNOWLEDGE_FILE` 均存在时：

1. **先导入应急知识** `emergency_knowledge.json`：读取 `topics` 列表，对每个主题 `MERGE EmergencyTopic` 并逐条 `MERGE GuidanceStep`，建立 `HAS_STEP`；再读取 `topic_relations` 在主题间 `MERGE RELATES_TO`。  
2. **再导入真实地震目录** `real_earthquakes_catalog.json`：遍历 `earthquakes`，对每条 `MERGE Earthquake` 并 `SET` 属性；若记录含 `region` 或可从 `location` 推断省名，则 `MERGE Region` 并建立 `OCCURRED_IN`；对 `links_to_topics` 中的主题 id 建立 `SUGGESTS_TOPIC`。

该顺序保证在关联地震与主题时，**应急主题节点已存在**，避免悬空关系。

**兼容路径（CSV）**  
若上述两 JSON 不同时存在，但存在 `EARTHQUAKE_DATA_FILE`（CSV），则按列映射导入 `Earthquake`，并根据 `location` 推断区域后建立 `OCCURRED_IN`，与旧版数据格式兼容。

**运行期更新**  
`update_from_realtime_data()` 调用外部接口获取新事件列表，对每条调用 `upsert_earthquake`：`MERGE` 按 `id` 更新属性并尽量重建与 `Region` 的 `OCCURRED_IN`，实现目录增量合并而不破坏已有应急子图。

## 4.2 面向问题的子图查询与触发规则

大模型路径下的图谱访问并非对自然语言做端到端语义解析生成 Cypher，而是采用**可解释的触发规则**：在应用层判断问句模式，再调用已封装的查询方法。以下与 `app.py` 中 `generate_response` 及 `Neo4jKG` API 一致。

### 4.2.1 区域、震级等事实性查询触发

**（1）省级地区触发**  
维护与图谱侧一致的省级名称表（如四川、云南、北京等）。对问句做子串匹配，命中第一个省名后调用 `query_earthquakes_by_region(region)`。Cypher 语义为：匹配 `Earthquake`，`WHERE e.location CONTAINS $region`，按 `time` 降序返回。应用层取前若干条拼入「知识图谱信息」段落，包含地点、时间、震级、深度、烈度与描述等字段。

**（2）震级阈值触发**  
当问句包含「震级」且同时包含「大于」或「高于」，并用正则提取其后的数值时，将该值作为最小震级，调用 `query_earthquakes_by_magnitude(min_magnitude)`（上界默认为 10.0）。结果按震级降序排列，应用层截取前若干条，格式化为「震级大于 x 级的地震」列表。

**（3）前端专用图谱查询（不经大模型）**  
`query_type: kg` 时，根据 `params.type` 调用 `all`、`by_region`、`by_magnitude`、`by_depth` 等接口，对应全量列表、地区包含过滤、震级区间与深度区间查询，供列表与筛选控件使用，保证**低延迟与结果可复现**。

上述规则侧重**高频、结构化**问法；未命中规则时不强行查询事件子图，避免无关 Cypher 开销。

### 4.2.2 应急主题与步骤类语境查询触发

当用户问题涉及避险、处置流程等语义时，调用 `query_emergency_context(user_text)`。  
首先进行**关键词触发**：若问句中未出现预设触发子串（如「怎么办」「避险」「避震」「应急」「自救」「余震」「室内」「室外」「演练」等），则直接返回空字符串，不向模型注入大段应急文本。

一旦触发，则在图库中执行模式：匹配所有 `EmergencyTopic`，对其经 `HAS_STEP` 关联的 `GuidanceStep` 做可选匹配，按主题 id 与步骤 `order` 排序；在 Python 侧聚合成「每个主题下列出有序步骤」的结构，并前缀标题 **【知识图谱·应急避险要点】**，每主题含标题、类别、分步条文及可选 `source` 说明。

该设计与 RAG 中的应急文本形成互补：**图谱侧**保证主题—步骤的图结构与顺序一致；**向量检索侧**可补充表述变体与长文片段（第 5 章）。

## 4.3 图谱上下文的生成与表示

### 4.3.1 查询结果到自然语言上下文的模板化拼接

应用层将 Cypher 返回的属性字典映射为固定模板的纯文本，便于直接嵌入大模型 user 提示。

**地区查询结果**  
每条事件按序号输出：地点与「地震」字样、换行缩进输出时间、震级、深度、烈度、描述等，多条之间空行分隔，整体冠以「【知识图谱信息】」。

**震级阈值结果**  
输出「【震级大于 x 级的地震】」标题，每条一行：地点、震级、时间摘要。

**应急语境结果**  
输出「【知识图谱·应急避险要点】」及多主题块，每块内为书名号标题、类别及编号步骤列表，必要时附参考说明行。

上述字符串在提示中与「【参考资料】」块并列，由第 3 章所述规则约定**事实优先级**（可验证事实以图谱为准）。

### 4.3.2 空结果与弱命中时的处理

**（1）无规则命中或查询结果为空**  
图谱侧累积字符串为空时，在写入提示前将【知识图谱】对应段落置为 **「（无）」**，明确表示当前未提供结构化命中，避免模型误以为缺失段落为省略。

**（2）关闭图谱上下文（消融或调试）**  
当配置 `KG_CONTEXT_ENABLED` 为假时，不执行上述查询逻辑，【知识图谱】段落固定为 **「（本路径已关闭）」**，便于与全量或仅 RAG 基线对比。

**（3）应急触发未命中**  
`query_emergency_context` 在未命中触发词时返回空串，不参与拼接；若触发但图中无主题步骤，返回空串，最终仍可能仅体现地区或震级块，或整体为「（无）」。

该策略保证提示结构**稳定、可解析**，并支持实验开关与错误分析。

## 本章小结

本章给出了地震应急知识图谱的**模式设计**（地震、区域、应急主题、步骤及主要关系与唯一约束）、**数据导入顺序与回退策略**（应急 JSON + 目录 JSON 优先，CSV 兼容，运行期 upsert），以及面向大模型路径的**规则触发式查询**（省名、震级阈值、应急关键词）与**模板化上下文生成**及空结果处理。第 5 章将在图谱之外补充向量检索与参考资料拼装；第 6 章给出与 Flask 及配置的完整对接说明。
