## 二、各模块功能说明

### 2.1 入口与配置

| 文件 | 功能 |
|------|------|
| `app.py` | Flask 主入口。启动时加载 Neo4j KG、LoRA 微调模型、RAG 索引、分类器、调度器等全部组件。定义 `/api/query`（文本问答）、`/api/multimodal-query`（图片问答）、`/api/update-data`（数据更新）、`/api/eval-set`（评测集）等路由。 |
| `config/config.py` | 全局配置类 `Config`，涵盖 Neo4j 连接、模型路径、推理参数、RAG/Milvus 配置、三阶段调度参数、动态源配置、高德地图配置等约 80 项。 |
| `config/constants.py` | 共享常量：`CHINA_REGION_NAMES`（32 个省级名称）和 `match_region_in_text()` 函数，供 KG 区域推断与问句匹配共用。 |

### 2.2 core/ — 核心业务模块

| 文件 | 功能 |
|------|------|
| `phase_classifier.py` | 三阶段问题分类器。基于关键词加权评分将用户问句分类为**震前/震中/震后/通用**，同时计算紧急度（urgency）和是否需要动态数据（need_dynamic）。关键词分 high/medium/low 三级权重。 |
| `dynamic_retriever.py` | 动态知识检索模块。从 `earthquake_feed` 获取实时地震数据，支持 TTL 缓存（默认 5 分钟），按阶段决定是否检索（震前不需要动态数据）。 |
| `earthquake_feed.py` | 统一地震动态数据源。支持 CEIC（中国地震台网）和 USGS FDSN API 两个数据源，可配置中国区域过滤、最小震级、时间窗口。多源结果自动去重合并，CEIC 优先。 |
| `scheduler.py` | 不确定性感知调度器。根据阶段分类结果和知识源探测信号，决定启用哪些知识源（KG/RAG/动态）及其优先级，生成阶段提示语和时效提示。 |
| `knowledge_signals.py` | 调度前知识源探测。探测 RAG 检索得分、KG 命中情况、动态数据可用性，综合计算静态置信度和动态可用性。 |
| `multimodal_output.py` | 多模态输出模块。从 `multimodal_resources.json` 加载资源定义，根据问句关键词和阶段标签匹配示意图/链接/视频资源。 |
| `amap_client.py` | 高德地图 Web 服务封装。提供地理编码、逆地理编码、步行路径规划、静态地图 URL 生成、导航 URL 生成。自动 WGS84→GCJ-02 坐标转换。 |
| `coord_convert.py` | WGS84 → GCJ-02 坐标偏移算法（国测局加密坐标），用于高德地图 API 坐标对齐。 |
| `geo_utils.py` | 地理计算工具集：Haversine 距离、坐标提取、城市名匹配、高德/百度/OSM 地图 URL 生成。 |
| `shelter_service.py` | 避难所静态库服务。从 `shelters.json` 加载数据，支持城市过滤、最近点检索、高德步行路径规划、导航链接生成。 |
| `aftershock_chart.py` | 余震震级时序图生成器。基于动态地震目录，用 Matplotlib 生成震级-时间折线图，保存到 `static/generated/`。 |
| `policy_rss.py` | 政府政策 RSS 抓取器。从应急管理部、国务院等 RSS 源抓取最新政策公告，带缓存（1 小时），失败时降级为固定门户链接。 |

### 2.3 kg/ — 知识图谱

| 文件 | 功能 |
|------|------|
| `neo4j_kg.py` | 基于 Neo4j 的地震知识图谱。节点类型：`Earthquake`（地震事件）、`Region`（区域）、`EmergencyTopic`（应急主题）、`GuidanceStep`（指导步骤）。关系类型：`OCCURRED_IN`、`HAS_STEP`、`SUGGESTS_TOPIC`、`RELATES_TO`。初始化时从 JSON 导入真实地震目录和应急知识。支持按区域/震级/深度/时间查询、应急上下文抽取、实时数据 upsert。 |

### 2.4 rag/ — 检索增强生成

| 文件 | 功能 |
|------|------|
| `emergency_rag.py` | 应急知识 RAG 核心模块。从 `emergency_knowledge.json` 加载 topic 级分块，预计算向量，查询时余弦相似度 Top-K。工厂函数 `build_emergency_rag_from_config()` 根据配置选择内存模式或 Milvus 模式。 |
| `milvus_rag.py` | Milvus 向量检索 RAG。与 `EmergencyRAG` 接口一致，底层使用 Milvus IP（内积）检索。自动创建/重建集合、写入向量、创建索引。 |

### 2.5 llm/ — 大模型相关

| 文件 | 功能 |
|------|------|
| `qwen_vl_handler.py` | Qwen2-VL 多模态输入处理器。懒加载模式，首次图片问答时才加载模型。接收 PIL Image + 文本上下文，端到端生成回答。 |
| `finetune_qianwen_distill.py` | QLoRA 微调脚本。使用 Qwen1.5-1.8B 基础模型，LoRA rank=8，3 轮训练，支持 MPS/CUDA/CPU。 |
| `prepare_sft_data.py` | 将 Ollama 生成的 JSONL 数据转换为 SFT 对话格式（system/user/assistant）。 |
| `convert_data.py` | 将 `train_data.json`/`val_data.json` 转换为 JSONL 格式。 |
| `merge_lora_weights.py` | 将 LoRA 适配器权重合并回基础模型，生成完整模型权重。 |

### 2.6 services/ — 应用服务层

| 文件 | 功能 |
|------|------|
| `context_builder.py` | **核心编排层**。`prepare()` 方法是整个系统的编排核心：PhaseClassifier 分类 → KnowledgeSignals 探测 → Scheduler 决策 → 组装 KG 上下文 + RAG 上下文 + 动态上下文 + 阶段指令 + 时效提示 + 多轮对话历史 → 生成完整 prompt。 |
| `output_enricher.py` | 第三层输出增强。模型生成回答后，根据问题和阶段附加：避难所导航+地图、震中位置图+导航、余震时序图、政策 RSS 链接。 |
| `response_guard.py` | 回答质量检测与降级。检测乱码/幻觉/低置信度回答，必要时降级为 RAG 检索摘要。 |

### 2.7 scripts/ — 辅助脚本

| 文件 | 功能 |
|------|------|
| `earthquake_api.py` | 实时地震数据获取与本地 JSON 缓存，调用 `earthquake_feed` 写入 `data/earthquake_data.json`。 |
| `run_ablation_eval.py` | 四基线消融实验（B0 无KG无RAG / B1 有KG无RAG / B2 无KG有RAG / B3 有KG有RAG）。 |
| `generate_*.py` | 论文配图生成脚本（系统架构图、查询流程图、RAG 流程图、KG 模式图等）。 |
| `format_thesis1.py` 等 | 论文 docx 格式化、同步、修补、润色等文档处理脚本。 |

## 六、系统架构总结

本系统是一个**面向地震应急领域的三阶段协同智能问答系统**，核心设计：

1. **三阶段分类与调度**：用户问题自动分类为震前/震中/震后，不同阶段启用不同知识源组合和回答策略。

2. **多源知识协同**：知识图谱（Neo4j，结构化事实）+ 向量检索（RAG，语义匹配）+ 动态震情（CEIC+USGS，实时数据），通过不确定性感知调度器动态组合。

3. **三层输出增强**：
   - 第一层：LLM 生成的文本回答
   - 第二层：关键词匹配的示意图/链接资源
   - 第三层：地图导航、避难所检索、余震时序图、政策 RSS 等富媒体增强

4. **多模态输入**：支持图片上传，通过 Qwen2-VL 端到端视觉理解。

5. **质量保障**：响应清洗 + 乱码/幻觉检测 + RAG 降级回退。

6. **本地化部署**：所有模型可离线运行，Docker Compose 一键启动 Neo4j 和 Milvus。
