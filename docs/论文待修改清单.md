## 二、表述夸大 / 与实现不符（降级措辞）

### 5. 「不确定性感知」「自适应调整知识源」过满
- **位置**：摘要、1.3.2 创新点、2.x/3.x 调度相关段
- **真相**：`Scheduler` 实质是关键词 + 阈值规则；代码中 `use_kg`/`use_rag` 基本恒为 True，主要切换的是动态源与提示约束；KG/RAG 开闭由配置项决定
- **改法**：改为「阶段先验 + 规则阈值调度」；写清主要自适应体现在动态源开关与 `prompt_suffix`/`reliability_hint`

### 6. 「显著优于 / 系统验证了有效性」与样本规模不匹配
- **位置**：创新点（3）、第7章、第8章
- **真相**：12 题、无显著性检验、无标注者一致性；且 B3 **要点完整性低于 B0**（2.69 vs 3.87）
- **改法**：写成「在 12 题快速消融中，B3 事实一致性最高」；承认完整性非最优；删「显著」「验证有效性」

### 7. QueryContextBuilder「并行」探测
- **位置**：2.1.2 文本问答流
- **真相**：主路径为串行：classify → signals → schedule → retrieve
- **改法**：改为「分步 / 依次」探测

### 8. CEIC 表述过「正式」
- **位置**：摘要、动态源、第7章案例、8.2 展望
- **真相**：`core/earthquake_feed.py` 走 CEIC `speedsearch` 页面接口 + USGS，非正式目录 OpenAPI；展望写「深化正式 API（当前已实现…）」自相矛盾
- **改法**：正文统一为「轻量 CEIC 抓取 + USGS FDSN」；展望写正式 API 待对接

### 9. 实验环境「全部在 CPU 完成」
- **位置**：第7章实验环境
- **真相**：`app.py` 设备优先级为 MPS → CUDA → CPU
- **改法**：写实际设备（或「本机自动选择」），附一次运行日志更佳
