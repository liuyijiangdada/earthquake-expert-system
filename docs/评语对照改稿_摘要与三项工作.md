## 问题定义（呼应「快、准、全」）

本文不声称更快或更全。主攻两件事：

1. **准（事实可核对）**：震级、时间、地点等参数须能对齐注入证据，而不是参数记忆。
2. **新（震情可更新）**：对「刚才/最新」类问句应接入动态速报，并在源不可用时明确降级，而不是编造。

困难命名（摘要只写表现，原因放第 1 章）：

| 名称 | 表现（读者可认同的现象） |
|------|--------------------------|
| 震情事实漂移 | 把历史震例参数说成「刚才发生」；或与台网/目录不一致的震级地点 |
| 阶段指导错位 | 震中问避险却答安置政策；震前准备问句却强调余震排查 |

要点完整性上，协同路径未必高于仅模型（旧 60 题 B3 完整性低于 B0），故摘要不得写「全面优于」。

## 摘要改写稿（待填实测数字）

地震应急问答覆盖震前准备、震中避险与震后安置，现有通用问答在两类困难上表现突出：一是**震情事实漂移**（把过时或虚构的震级、地点当作当前事件）；二是**阶段指导错位**（不同阶段的条文被混用）。针对上述困难，本文构建动态—静态知识协同的地震应急问答系统：静态侧以「地震事件—地区—应急主题—指导步骤」图谱与主题检索提供可核对证据；动态侧以冻结可复现的台网/目录速报提供时效事实；调度侧用三阶段规则阈值决定动态源启闭与提示分区。主要工作如下：

（1）面向应急主题的静态知识联合表征。基于应急手册与典型震例构建图谱模式及主题向量索引，以结构化查询与语义召回获取静态证据。

（2）三阶段规则调度算法。震前默认关闭动态源；震中优先对齐速报字段；震后按紧急度与动态可用性开关。协同体现在「分区注入 + 动态开关 + 可靠性提示」，而不是关闭图谱。敏感性实验给出默认阈值下各阶段 `use_dynamic` 比例及阈值扰动时的决策翻转。

（3）系统实现与实验。实现分类—探测—调度—检索—组装—生成的可运行系统。评测含：B0–B3 静态消融；B4 仅动态、B5 全源加动态（冻结快照）；B3-ns 关闭阶段调度的对照；旧/归一化两套自动分并列；以及 20 题人工评测表（全量 60 题人工仍待完成）。

本轮可写入正文的调度数字（无需 LLM）：默认阈值下动态源开启率震前 15%、震中 55%、震后 35%；B3 阶段标签率 76.7%，关掉分类/调度的 B3-ns 为 0。生成质量数字须用实测自动分（见下表），禁止再用校准后的 82.5%。自动分仅为 proxy，不替代 20 题人工表。

**关键词：** 地震应急问答；动态—静态协同；知识图谱；向量检索；三阶段规则调度；事实一致性

## Algorithm 4-1 符号 → 代码

| 伪代码 | 实现 | 输入 / 输出 |
|--------|------|-------------|
| Classify | `PhaseClassifier.classify` | 问句 → phase, confidence, urgency, need_dynamic |
| ProbeGraph | `compute_knowledge_signals` 中区域/震级/应急主题探测；渲染见 `QueryContextBuilder._build_kg_context` | 问句、phase_tag → hit 标记与 snippet |
| ProbeRAG | `EmergencyRAG.search`（经 `compute_knowledge_signals` / `build_rag_section`） | 问句 → hits, rag_top_score |
| ProbeDynamic | `DynamicRetriever.fetch_for_phase`；评测时 `apply_frozen_snapshot` | phase、快照 → items, dynamic_availability |
| Schedule | `Scheduler.decide` | PhaseResult + KnowledgeSignals → ScheduleDecision |
| Combine | `QueryContextBuilder.step_retrieve_sections` + `step_build_prompt` | 分区【知识图谱】【参考资料】【动态信息】 |
| RenderGraph | `_build_kg_context` / `JsonEvalKG.query_*` | 结构化字段文本 |
| Generate | `app.generate_response`（评测 `_infer_once`） | prompt → 回答 |
